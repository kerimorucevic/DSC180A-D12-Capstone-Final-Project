# AI usage

Scope: everything in `EDA/subscription_recurrence/`.

## Tools

Claude Code (Anthropic), run locally in an editor on a team member's laptop, over one working session on 2026-11-24.
Claude Opus 5.5 did the codebase review and the initial implementation; Claude Sonnet 5.5 applied the research lead's
methodological decisions and prepared this publication package.

## What the AI produced

* A read-only review of the team's existing notebooks and data files (methodology, dependencies, limitations).
* All files in `subrec/`, `tests/`, `scripts/`, `docs/`, the notebook `subscription_recurrence_analysis.ipynb`,
  `README.md`, `requirements.txt` and `.gitignore`, **except** the rule block in `subrec/rules_baseline.py`, which is a
  verbatim copy of the team's PA7 notebook (cell 3) and was not edited.
* The v2 classifier keyword lists, the implementation of M1–M3, the synthetic test scenarios, the synthetic data generator
  and the review-sampling code. The recurrence definitions themselves (M0–M3, thresholds, populations) came from the
  team's research specification; the research lead's decisions of 2026-11-24 were applied as instructed.
* Execution of the synthetic tests and of the notebook in synthetic mode. Test results are recorded in `docs/TESTING.md`.

## What the AI did not do

* It did not access, read or process the restricted transaction data, the team's DSMLP environment, GitHub or any other
  external service. Every number it produced came from synthetic data generated by `subrec/synthetic.py`.
* It produced no real-data results and made no claim about which recurrence definition is more accurate.
* It did not run any financial-distress prediction.
* It did not commit, push or modify any other team file. The package was prepared in a separate folder for review.
* The only check of the real-data code path was a dry run on a synthetic parquet file shaped like the cache.

## What still needs human review

* The v2 classifier's merchant dictionary and exclusion rules are the AI's judgement calls and are **provisional**; check
  them against real memos on DSMLP (`private/classifier_disagreements.csv`).
* The human-review labelling procedure has been implemented but not carried out. No accuracy claim is supported until it is.
* The code and documentation have not been independently reviewed by a human. Review the logic in `subrec/recurrence.py`
  and `subrec/coverage.py` in particular, and run the real-data notebook on DSMLP before relying on any output.
* `subrec/rules_baseline.py` is a verbatim copy of the team's PA7 rules. The AI scanned its keyword text for personal
  information and identifiers and found none, but flagged merchant-specific, locale-revealing and sensitive-category
  tokens (derived from real memos) for a team decision; nothing was changed. The team must confirm it is comfortable
  publishing them.
* Write the *Findings* section of any real-data `analysis_summary.md` yourselves; the generator deliberately leaves it blank.
